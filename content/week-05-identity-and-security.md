# Week 5: Identity and Security

## Goals

- Learn authentication vs authorization.
- Practice least privilege, roles, MFA, encryption, and audit logging.
- Build a habit of treating security as a default design concern.

## Core resources

- [What is IAM?](https://docs.aws.amazon.com/IAM/latest/UserGuide/introduction.html)
- [Getting Started with IAM](https://docs.aws.amazon.com/IAM/latest/UserGuide/getting-started.html)
- [IAM Security Best Practices](https://docs.aws.amazon.com/IAM/latest/UserGuide/best-practices.html)
- [AWS KMS Concepts](https://docs.aws.amazon.com/kms/latest/developerguide/concepts-intro.html)
- [What Is AWS CloudTrail?](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/cloudtrail-user-guide.html)

## Exercises

1. Create an access matrix for three personas: `admin`, `developer`, and `read-only analyst`.
2. Write three least-privilege rules you would enforce for a new cloud account.
3. Decide which data in a sample app should be encrypted at rest and in transit.
4. List five cloud events you would want logged for audit and incident response.
5. Explain why long-term credentials should be minimized.

## Deliverable

- One access matrix
- One security checklist
- One short audit-logging plan

## Exit check

You are ready for week 6 if you can explain the difference between a user, a role, a policy, and an audit trail.
